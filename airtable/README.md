# הבסיס ב-Airtable

הדשבורד קורא את הלידים מבסיס בשם Leads Dashboard, מטבלה בשם Leads. שמות השדות והסוגים שלהם מפורטים באפיון, בסעיף "הטבלה ב-Airtable".

הקובץ `leads-seed.csv` שבתיקייה הזו הוא נתוני ההתחלה של הפרויקט: 260 לידי דמה, עם שמות, עסקים ומספרי טלפון בדויים. הוא משמש גם כתבנית למי שרוצה לחבר בסיס משלו.

## חיבור בסיס משלכם לדשבורד

### 1. בסיס מהתבנית

1. מורידים את הקובץ [leads-seed.csv](leads-seed.csv). בעמוד של הקובץ ב-GitHub יש כפתור הורדה.
2. ב-Airtable יוצרים בסיס חדש, בוחרים ייבוא מקובץ CSV ובוחרים את הקובץ.
3. שמות העמודות בקובץ הם שמות השדות שהדשבורד מחפש. אפשר להשאיר את השדות כטקסט, כי הדשבורד יודע לקרוא מספר ותאריך שנשמרו כטקסט.
4. בשדות `source`, `status` ו-`budget` הערכים צריכים להיות מהרשימה שבאפיון, באנגלית או בעברית. רשומה עם ערך אחר תדלג, והדשבורד יראה כמה רשומות דולגו ולמה.

### 2. מפתח גישה

1. נכנסים לעמוד [יצירת מפתחות ב-Airtable](https://airtable.com/create/tokens) ויוצרים מפתח חדש.
2. מוסיפים את ההרשאה `data.records:read`. כדי שגם שינוי סטטוס וליד חדש יישמרו, מוסיפים גם את `data.records:write`.
3. בגישה לבסיסים בוחרים רק את הבסיס שיצרתם.
4. מעתיקים את המפתח. Airtable מציג אותו פעם אחת בלבד.

### 3. המזהים של הבסיס והטבלה

פותחים את הטבלה ב-Airtable ומסתכלים על הכתובת בדפדפן. החלק שמתחיל ב-app הוא ה-Base ID, והחלק שמתחיל ב-tbl הוא ה-Table ID. אפשר להזין גם את שם הטבלה במקום ה-Table ID.

### 4. החיבור בדשבורד

בדשבורד לוחצים על "חיבור ל-Airtable", מזינים את המפתח, את ה-Base ID ואת ה-Table ID, ולוחצים על "התחברות". הדשבורד בודק את החיבור לפני שהוא עובר לנתונים שלכם.

המפתח נשלח רק ל-Airtable. בלי הסימון "לזכור את המפתח בדפדפן הזה" הוא נמחק ברענון של הדף. כפתור הניתוק מחזיר לנתוני הפרויקט.

## נתוני הפרויקט

הבסיס של הפרויקט מחובר לדשבורד דרך פונקציה ב-Supabase, שמחזיקה את המפתח כסוד ולא חושפת אותו לדפדפן. הפונקציה ממלאת טבלה ריקה מהקובץ `leads-seed.csv` בפעולת מילוי ראשוני. הפרטים באפיון, בסעיף "שכבת השרת ב-Supabase".
